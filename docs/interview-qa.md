# OfferHelper 项目面试问答准备

> 站在面试官视角，预判可能的提问，并给出回答思路。
> 项目：AI 求职助手 OfferHelper（Web + MCP Server + Claude Skill）
> 技术栈：Next.js 16 · React 19 · Supabase · Claude API / OpenAI 兼容接口 · TypeScript

---

## 一、项目整体 & 动机类

面试官想确认：这是不是你真正主导的项目，你对它的理解有多深。

**Q1：用一句话介绍这个项目，以及你为什么做它？**
- 思路：先说清楚「给谁用、解决什么问题」，再说「我做了什么」。
- 参考："OfferHelper 是我独立开发的 AI 求职助手，面向应届生和实习生，把简历分析、岗位匹配、面试训练、优势挖掘四件事做成一个产品。我不只是调 API，而是完整走了从产品设计、全栈实现到发布上线（含 MCP、Skill 生态集成）的全过程。"

**Q2：这个项目是你一个人做的吗？AI 辅助了多少？**
- 诚实回答：用 Claude Code 辅助开发，但架构、技术选型、功能定义、bug 排查决策都是我做的。
- 强调：AI 提升实现速度，判断"做什么、怎么设计"是我的工作。（这是加分项，不是减分项——说明你掌握了新的开发范式）

**Q3：这个项目现在有真实用户吗？数据量多大？**
- 如实说。如果用户少，就讲"目前是 MVP，重点验证功能和技术可行性"，不要夸大。

## 二、AI 工程类（最可能深挖的部分）

面试官想确认：你是真的懂 LLM 工程，还是只会调接口。

**Q4：你提到"双模型架构"，具体是什么？为什么这么设计？**
- 主力模型做深度分析（简历评分、面试评估），快速模型做摘要/推荐。
- 理由：深度任务需要强模型保证质量，轻量任务用快模型省成本、降延迟。这是成本与质量的权衡。

**Q5：为什么要做"双环境兼容"（本地 Anthropic SDK + 线上 OpenAI 兼容接口）？怎么实现的？**
- 本地开发走 Anthropic SDK（Hyperspace 代理），线上用硅基流动（OpenAI 兼容）。
- 实现：抽象了一个 AI Client 层，统一 `chat.complete` 接口，内部根据配置分派到不同 SDK。业务代码不感知底层是哪家。
- 关键点：Anthropic 的 system 是独立参数，OpenAI 是 messages 里的一条，抽象层处理了这个差异。

**Q6：流式输出（SSE）是怎么做的？为什么要用流式？**
- 后端用 `ReadableStream` 逐行输出 NDJSON，前端 `getReader()` 逐块解析。
- 理由：简历分析、面试评估耗时几秒到几十秒，流式让用户即时看到进度，体验接近 ChatGPT，而不是干等。

**Q7：如果 AI 返回的格式不对（比如该返回 JSON 却返回了别的），你怎么处理？**
- 这个问题你有真实经历可讲：面试题目 AI 可能返回 4 道或 6 道而非 5 道，我在后端做了规整（过滤空值、截断到 1-5 道），前端也从硬编码改成用实际数组长度。
- 体现：对 AI 输出不确定性有防御性设计。

**Q8：AI 调用失败、超时、流中断了怎么办？**
- 真实经历：面试评估流中途断开会让前端卡在 loading，我加了"流结束但没拿到结果就切回可重试状态"的兜底。
- 体现：考虑了 happy path 之外的失败路径。

**Q9：Prompt 是怎么设计的？怎么保证输出稳定？**
- 讲你的评分框架（面试三维评分：结构/证据/岗位关联）、优势挖掘的多轮追问逻辑。
- 稳定性：用明确的输出格式约束 + 结构化字段。

**Q10：简历里的手机号、邮箱这些隐私信息怎么处理？**
- 真实经历：AI 格式化时敏感信息会触发内容过滤导致截断，我改成检测到手机号/邮箱直接替换成占位符 `[电话]`/`[邮箱]`——既保护隐私又绕过过滤。
- 后来更进一步：简历格式化直接改成规则实现（正则识别章节/日期/列表），不再走 AI，更快、免费、不出错。
- 体现：做技术决策时会权衡「AI vs 规则」，不是无脑上 AI。

## 三、系统设计 & 架构类

**Q11：用户的 API Key 怎么存储？安全吗？**
- AES-256-GCM 加密存储，不明文落库。
- 有个真实的坑可以讲：早期前端加载时把密文回填到输入框，用户再保存会二次加密损坏 Key——我后来改成脱敏 GET 接口，只返回"是否已配置"布尔值，不下发密文。
- 体现：踩过坑，也理解了"密钥材料不应下发到客户端"的原则。

**Q12：限流是怎么做的？怎么防止被刷？**
- 游客按 IP 限额、登录用户按 user_id 每日限额、加 60 秒滑动窗口速率限制。
- 用 Postgres 的原子 RPC 一次往返完成检查+记录，避免并发绕过。
- RPC 失败时 fail-closed（拒绝请求），而不是放行。

**Q13：数据库权限怎么控制的？**
- Supabase RLS（行级安全），每个表按 user_id 隔离。
- service role client 绕过 RLS 的地方，手动加 user_id 过滤兜底。

**Q14：多轮对话（面试、优势挖掘）的状态怎么管理？**
- 服务端存 session，前端传 session_id + turn_index 推进。
- API 是无状态的，每次带完整上下文。
- 可以坦诚：这里有个设计权衡，多轮状态放前端维护还是后端，我选了后端存 session、前端传游标。

## 四、MCP & Skill（差异化亮点，主动引导面试官问）

**Q15：MCP 是什么？你为什么要做一个 MCP Server？**
- MCP 是 Anthropic 2024 年底推出的工具协议标准，让 Claude 这类 AI 能调用外部工具。
- 我把 OfferHelper 四大功能封装成 MCP 工具，发布到 npm，技术用户在 Claude Desktop / Cursor 里能直接调用，不用开浏览器。
- 体现：跟进 AI 生态最新进展，并且真正落地（发了 npm 包、做了一键安装 CLI）。

**Q16：MCP Server 的鉴权怎么做的？**
- 设计了 API Token 体系：用户在设置页生成 token（SHA-256 哈希存储，明文只显示一次），MCP 用 Bearer Token 调用后端。
- 有真实的坑：一开始限流层只认 Session Cookie，MCP token 用户被当游客，配额错乱——后来让限流和 AI 配置层都能接收 token 用户 ID。

**Q17：Claude Skill 和 MCP 有什么区别？**
- MCP 是工具调用协议（给 AI 一个能调的工具）；Skill 是给 Agent 的"专家知识包"，按需加载领域知识和工作流。
- 我为 OfferHelper 做了 Skill，包含 7 个知识模块（简历评分、岗位匹配、面试训练、优势分类、追问规则、引导流程、安全边界）。
- 体现：理解 AI 生态里不同层次的集成方式。

**Q18：这些 MCP/Skill 真的有人用吗？做它的意义是什么？**
- 诚实：目前受众是技术用户，量不大。
- 但意义在于：证明我能把产品能力做成开发者工具、跟得上 AI 工具链演进——这是比"又写了个 CRUD"更能体现 AI 工程能力的东西。

## 五、工程质量 & 反思类（面试官爱问，最能体现成熟度）

**Q19：这个项目你遇到过最难的 bug 是什么？怎么解决的？**
- 强素材：PDF 解析在本地正常、线上失败。
- 排查过程：先怀疑提取库，逐个换（unpdf → pdf-parse → pdf2json → pdfjs-serverless），看 Vercel 日志发现是 `@napi-rs/canvas` 缺失 + 内容过滤截断，最后定位到根因是"线上 serverless 环境的 wasm/native 依赖限制 + AI 内容过滤"两个叠加问题。
- 体现：系统化排查（看日志、二分定位、对比本地线上差异），而不是瞎试。

**Q20：如果让你重做这个项目，你会改什么？**
- 可以说：早期没做好错误处理和边界情况（很多 SSE 流中断、空输入的兜底是后来补的）；如果重来会一开始就把"失败路径"设计进去。
- 或者：AI 格式化那块走了弯路，后来发现规则实现更合适——会更早评估"这个场景真的需要 AI 吗"。

**Q21：你怎么保证代码质量？做测试了吗？**
- 诚实回答现状。如果没写自动化测试，就讲你怎么手动验证的、TypeScript 类型检查、code review（哪怕是 AI 辅助 review）。
- 可以讲：我做过一次系统性的功能审查，分模块排查逻辑缺陷，发现并修了一批 bug（密钥损坏、面试卡死、删除竞态等）。

**Q22：项目部署在哪？CI/CD 怎么做的？**
- Vercel，push 到 main 自动部署。
- 数据库迁移在 Supabase 手动执行（可以说未来会做成 migration 自动化）。

## 六、可能的"压力问题"（提前想好，别被问懵）

**Q23：这些功能 ChatGPT 直接问不就行了，你的产品价值在哪？**
- 回答方向：结构化（三维评分、多轮追问框架）、领域知识沉淀（评分 rubric）、可追溯（历史记录、进度追踪）、降低使用门槛（应届生不会写 prompt）。

**Q24：AI 生成的建议可能是错的，你怎么对用户负责？**
- 明确边界：不编造经历、不承诺 offer、不自动投递（这些在 Skill 的安全边界里有定义）。
- 输出区分事实/推断，让用户自己判断。

**Q25：你对 AI 应用开发的理解是什么？**
- 收尾性问题，讲你的认知：AI 应用的难点不在调 API，而在处理 AI 输出的不确定性、成本控制、把 AI 能力包装成可靠的产品体验、以及跟上快速演进的生态（MCP/Skill/Agent）。
